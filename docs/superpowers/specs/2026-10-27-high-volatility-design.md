# 多币波段系统完整高波动版设计

## 目标与边界

在现有 React、Hono/tRPC、Drizzle、MariaDB/MySQL 项目中完成可用于长时间模拟验证的高波动版本：修复模拟结算与回测正确性，增加正常、高波动、极端三态，100–150 合约 WebSocket 风险监测，统一开仓风控和可复现测试。始终保持公开行情和模拟交易，不接入密钥或真实订单。

已选择 TypeScript 优先。现有 Rust 服务保持回环地址和订单链路隔离，不作为正式信号或风控来源；本次仅确保其现有代码可编译测试，不宣称 TS/Rust 一致性验收完成。

## 非目标与验收边界

- 不承诺盈利能力、实盘就绪或完整交易所账户模型。
- 不用未收盘 K 线生成正式入场信号。
- 不把缩短扫描时间等同于增加交易频率，不自动提高杠杆或补仓摊平。
- 自动化验收覆盖单元、集成、数据库、API、浏览器和可控异常场景。连续数天模拟运行必须另计真实时长；代码完成时不冒充该项已通过。
- 历史盘口、真实冲击和全量账户维持保证金档位不可得时，明确记录模型近似，不伪造精度。

## 方案取舍

采用单一 TypeScript 权威实现：同一套纯函数提供信号、三态判定、仓位和风险计算，实时模拟与回测共用。相比 TS/Rust 同步重写，减少双实现漂移和部署复杂度；相比仅修补现有函数，能避免实时与回测规则继续分叉。Rust 后续只在可测量性能需要及一致性双跑通过后承担影子特征计算。

## 核心结构

### 1. 纯领域模块与数据契约

新增 `api/services/strategy.ts`、`volatility.ts`、`risk.ts` 和可测试的持仓管理纯函数。`contracts/trading.ts` 增加 `VolatilityMode = NORMAL | HIGH | EXTREME`、行情质量、状态迁移、组合止损风险、监测指标和审计视图。数据库增加波动配置字段、每币状态表及持仓初始风险字段；提供可重复执行的 Drizzle SQL 迁移，兼容 MariaDB 与 MySQL。

设置首版默认：7 天 5M ATR 分位数基线（至少 2016 根，不足则禁止新开仓）、90/99 分位数、1M 跳动 3/5 个滚动标准差且带最小波动下限、高波动连续 2 次确认、恢复稳定 180 秒、正常扫描 45 秒、高波动风险检查 10 秒、极端立即生效。所有参数经 Zod 校验，明确标为待回测校准而非最优值。

### 2. 一致行情与 WebSocket 监测

重构 `binance.ts`：一次行情快照只能来自单一数据源，缓存键包含数据源；主网/测试网切换整代失效，禁止跨源混合 K 线、盘口和标记价。验证 bid/ask/mark/时间戳有限、为正、顺序合理且新鲜，缓存不能掩盖过期数据。

新增 WebSocket 监测器，订阅交易池的 1M K 线、标记价和盘口，按交易所限制分连接、重连和记录延迟/丢包/限流。WebSocket 中断时 EXTREME 禁止开仓，REST 只作受控补全，不每几秒对全部合约轮询。1M 和未收盘数据只用于风险预警；正式信号仍由已收盘 4H/1H/15M/5M 计算。

### 3. 三态状态机

`volatility.ts` 输入同一币种的 ATR 基线、1M 收益滚动标准差、当前/基线点差和行情质量，输出目标状态与原因。NORMAL 维持现有短波段；HIGH 降低风险预算并加快风险重估，不增加信号频率；EXTREME 立即禁止新开仓并优先管理已有持仓。

状态表保存当前模式、连续确认次数、稳定起点、指标、最近数据时间和版本。高波动需连续两次，极端不等确认；退出需连续稳定 3–5 分钟，数据刚恢复但未稳定时保持保护状态。每次迁移写审计事件。恢复后重新生成信号，不执行积压机会；开仓使用信号收盘时间和状态版本拒绝陈旧信号。

### 4. 正确且原子的模拟执行

`paper.ts` 开仓前重新读取当前单一来源盘口与三态，检查状态、行情新鲜度、点差、滑点、信号年龄/偏离、方向、日损、持仓数、单笔与总保证金、组合总止损风险、同方向高相关敞口和强平缓冲。成交价基于当前买卖侧而非旧信号价，按实际成交价重新计算初始止损距离、2.2R 目标、数量、费用和保证金。

数量以实际止损距离、双边手续费和双边不利成交成本计算；高波动使用缩减后的风险预算。新增组合总止损风险上限（默认权益 1%）及同方向高相关风险上限（默认 0.5%，15M 收益相关系数绝对值 ≥0.8 视为高相关），所有路径统一经过同一风险审批。

数据库事务锁定模拟账户行，串行化跨进程开仓/平仓检查与账户变更；账户金额用原子增量更新。修正 Drizzle mysql2 的 `[ResultSetHeader, fields]` 结构读取，条件更新影响行数为 0 时抛错回滚。持仓保存不可变的 `initialRisk`，R 倍数不再从会移动的止损或滑点后的目标反推。行情不可用时不擅自用陈旧价平仓，记录并持续重试；紧急停止保持暂停并报告未平仓项。

### 5. 多标的同步组合回测

已确认升级为多标的同步组合回测，不保留单标的单仓作为完整版终点。按统一时间轴对齐各合约已收盘 K 线，共享账户权益、持仓组合、日损和三态状态；复用正式信号、组合风险、仓位和持仓管理纯函数。使用真实初始权益、下一根开盘成交、手续费、双边滑点和历史资金费率，结果包含组合权益、逐币交易、资金费用、风险拒绝和状态迁移。

每根 K 线先按保守顺序处理强平/止损/目标，再在收盘后确认移动止损，移动只对后续 K 线生效；跳空穿越强平或止损时按可实现的保守价格处理。期末退出同样计滑点，权益回撤纳入盘中不利高低价。增加资金费率结算和跳空、极端波动、点差失控、断流场景。历史点差不可得时使用明确配置的摩擦模型，不声称重建真实盘口。保存假设、数据缺口、资金费用和异常场景结果；缺数据时按失败关闭处理，不能用未来数据补齐。

### 6. 页面与可观测性

风险页增加三态参数、组合风险上限和当前 NORMAL/HIGH/EXTREME 数量；交易池显示每币状态、数据年龄、ATR 分位、跳动倍数与点差；总览显示组合总止损风险、WebSocket 延迟/重连/限流和状态迁移日志。修正仍写“180 分钟”的旧文案为 72 小时。保持现有终端视觉风格，移动端可横向滚动数据表。

### 7. 测试与运行验收

先用失败测试固定每个已确认缺陷，再实现。至少覆盖：平仓只结算一次且账户/订单/交易一致；跨事务并发开仓不超预算；非正/交叉/陈旧盘口拒绝；三态进入/立即极端/延迟恢复；恢复后不执行旧信号；费用后单笔和组合风险不超限；主网/测试网缓存不混用；同根 K 线移动止损不前视；强平跳空、资金费率、期末滑点和盘中回撤。

执行 `npm run check`、`npm test`、`npm run lint`、`npm run build`、`cargo test`。用独立测试数据库跑 Drizzle 迁移及真实并发集成测试，再启动生产服务，验证首页、风险页、交易池、Dashboard/API、MariaDB 持久化和公开 WebSocket 行情。自动交易默认暂停；只有全部模拟验收通过后才允许用户手动开启。最后启动连续模拟浸泡并明确其独立验收状态。

## Composer 决定项

- 指标取最严重状态：行情质量失效、点差超过硬上限、ATR 达 99 分位或 1M 跳动达 5σ 任一满足即 EXTREME；否则 ATR 达 90 分位、跳动达 3σ 或点差达自身近期中位数 2 倍任一满足即 HIGH。点差基线至少需 120 个有效样本，不足时禁止新开仓。
- HIGH 的单笔风险预算倍率为 0.5；不因 HIGH/EXTREME 自动收紧已有持仓止损或强制平仓，已有仓位继续执行强平、止损、目标和日损管理，EXTREME 只禁止新增风险并提高重估频率。
- 组合风险按每仓当前止损到现价的剩余不利风险计算，含预计退出费用和滑点；止损已越过保本后该仓风险贡献为 0，不用初始风险长期占满预算。相关性使用最近 60 根已收盘 15M 收益；已有持仓时样本不足则暂停新增，首仓无需相关样本。
- 数据故障按受影响合约隔离；只有共享行情源整体故障才暂停整个池。新鲜 REST 可补全并启动恢复稳定计时，不要求 WebSocket 必须先恢复，但 180 秒内持续有效才解除保护。盘口和标记价超过 5 秒、1M 数据超过 90 秒视为陈旧；陈旧价格只能记录风险告警，不能作为正常成交价。
- 正式开仓信号默认最多保留 15 秒；当前 mid 相对信号 entry 的偏离超过 `max(0.1%, 0.25 × ATR15/entry)` 时拒绝并等待重新分析。
- 默认监控和信号池 100 个，配置允许 2–150 个，按流动性排序；不再保留较小的独立监控池。
- 首版组合总止损风险 1%、高相关同方向风险 0.5%、相关系数 0.8、恢复 180 秒，均是保守的可配置工程默认值，需后续回测校准。
- 基线未完成和行情数据不可信时采取禁止新开仓，而非在数据不足时假设正常。
- 当前 Rust 不参与正式交易，不等待 Rust 一致性作为 TypeScript 高波动版上线模拟预览的前置条件。
- 用户已确认采用多标的同步组合回测，以验证组合风险、相关性、三态和日损，而不是仅保留单标的近似。
