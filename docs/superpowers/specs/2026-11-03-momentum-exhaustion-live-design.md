# 动能衰竭检测与真实持仓保护设计

## 目的

把已有 `main` 分支的多周期动能衰竭分析移植到当前真实交易分支，并按用户选择增加自动止损收紧和衰竭平仓。系统仍需保留原有短波段、早期动量入场、组合风控和紧急退出，不恢复任何管理员入口或只读限制。

## 目标

- 使用已收盘 15m、1h、4h K 线计算 RSI 背离、MACD 柱收缩、ROC/推进效率衰减、ADX 回落和放量反转。
- 对多头使用空头衰竭评分，对空头使用多头衰竭评分；展示 0–100 分、共振周期数、保护等级和结构破位。
- 衰竭评分降低新 SWING 信号评分，但不可单独制造入场或反手信号。
- 对系统管理的 MOMENTUM 持仓：`WARN` 仅提示；`TIGHTEN` 和 `REDUCE_CANDIDATE` 只允许单调收紧止损；`EXIT_CANDIDATE` 通过现有 reduce-only 平仓链退出。
- 同一衰竭评估可同时用于组合回测诊断，但回测默认只记录事件，不伪造成交表现。

## 非目标

- 不自动加仓、摊平、反手或恢复开仓。
- 不接管未知人工持仓，不删除外部订单/持仓对账问题。
- 不把评分宣称为盈利保证，不在本次部署中执行真实 canary。
- 不合并旧 `main` 的管理员认证、旧模拟执行器或过时 Rust 代码。

## 方案选择

1. **直接合并整个 `main`**：会删除当前真实下单、凭据存储、Rust 动量服务并恢复管理员入口，拒绝。
2. **只做预警与扣分**：实现较简单，但用户已明确选择自动收紧和平仓，不作为最终范围。
3. **选择性移植分析器并扩展现有执行适配器**：保留当前账户、订单状态机、原生止损和对账体系，增加最小保护接口。采用此方案。

## 检测与动作

- 数据：只使用 `closedCandles` 过滤后的 15m/1h/4h 数据；每周期至少 35 根且指标有效，否则 `NONE`，不动作。K 线必须时间递增、无重复、无缺口，OHLC 和成交量有效。15m/1h/4h 最新收盘分别不得陈旧超过 45 分钟、3 小时、9 小时。
- 加权评分：15m 50%、1h 30%、4h 20%。单周期分数至少 50 才计为共振，至少两个周期才构成共振。LONG 使用 bearishScore，SHORT 使用 bullishScore。
- `WARN`：加权分数至少 30，仅记录系统事件。
- `TIGHTEN`：分数至少 50 且共振。
- `REDUCE_CANDIDATE`：分数至少 70 且共振；本版不新增部分减仓，按收紧止损处理。
- `EXIT_CANDIDATE`：分数至少 70、共振，且最新已收盘 15m 突破此前五根 K 线（不含最新一根）的反向结构边界；优先于收紧并调用平仓。
- 收紧公式：ATR 使用已收盘 15m 的 14 周期值。LONG 候选为 `max(标记价 - ATR, 最近五根已收盘 15m 最低价 - 0.1ATR)`；SHORT 为 `min(标记价 + ATR, 最近五根已收盘 15m 最高价 + 0.1ATR)`。LIVE 按 tickSize 对 LONG 向下、SHORT 向上舍入。
- 舍入后再次验证：多头新止损必须大于旧止损且低于标记价，空头必须小于旧止损且高于标记价。相同、更宽松或无效候选不产生请求。

## 执行链路

- 仅在定时持仓管理中评估衰竭，不在 Rust 高频 frame 上新增三组 K 线请求。现有 `manageMomentumExits` 继续负责 120 秒无跟随和流向反转。
- 扩展执行适配器的单调止损收紧接口。Paper 使用数据库条件更新保证单调；LIVE 复用原生 STOP_MARKET 替换，只有交易所确认 NEW 且价格一致后才更新本地止损。
- 每次收紧都重新读取当前持仓、止损和 `exitPending`，并在持仓级串行临界区内重新验证候选价；普通移动止损、衰竭收紧、人工平仓和紧急退出不得用后完成的宽松值覆盖更严格值。
- 衰竭退出先取得与旧动量退出相同的持久化 claim，再调用本轮已选择的同一 adapter，不能重新选择执行模式。已提交或 UNKNOWN 保留恢复信息；异常按 lease 过期恢复；CANCEL 且仍有持仓不得当作成功，必须支持新的受控重试订单。
- 数据源和 `sourceGeneration` 在 K 线请求前后必须一致；单币读取失败只记录并跳过该币，不中断其他持仓。部署前已有的受管 MOMENTUM 持仓重启后仍受保护，SWING 与外部人工持仓不由该模块处理。
- 私有流、对账或估值异常时不得新增仓位。收紧必须有有效标记价；LIVE 的 reduce-only 平仓可在估值失效但K线有效时执行，Paper 无有效价格则保留仓位并告警。
- 未 armed、`autoTrade=false`、关闭新的 MOMENTUM 入场均不得阻断已有仓位的风险降低动作。止损替换存在撤旧单到确认新单的窗口，不宣称全程都有旧原生止损。
- LIVE 收紧失败沿用告警和 reduce-only 退出兜底；Paper 失败只告警并保持原止损，不伪造交易所兜底。

## 可观测性与兼容性

- 首页机会队列显示衰竭分数、共振、保护等级和结构状态；旧结果没有字段时显示等待重新扫描。
- 持仓 WARN/TIGHTEN/EXIT 通过现有系统事件输出，以持仓、动作和 15m 收盘时间去重；真实订单和退出原因继续使用现有页面。
- 组合回测保存全部影子事件，界面只展示最近六次；这些是 SWING 历史持仓观察，不是 MOMENTUM 自动平仓绩效，且不改变止损、成交或权益。
- 真实订单、持仓、凭据、armed、自动交易默认状态均不因部署而改变。

## 验收

- 与 `main` 固定样本同分；覆盖 LONG/SHORT、30/50/70 边界、单/双周期共振、结构窗口、EXIT 优先级以及 NONE/WARN 零交易动作。
- SWING 扣分精确且不制造方向、反手或 READY；不擅自增加新的最低分开仓门槛。
- 覆盖止损公式、tick 舍入、越过标记价、相同/宽松值零请求、最新止损并发单调性和 exitPending 短路。
- 覆盖撤单超时、替换 UNKNOWN、NEW 后数据库失败、部分成交及兜底平仓失败；CANCEL 不误记为成功。
- 覆盖持久化 claim、多进程/重启恢复、人工平仓竞争、未 armed 和 autoTrade=false 风险降低、无效估值、数据源切换和单币失败隔离。
- 完整 TypeScript 测试、类型检查、lint、构建及相关 Rust 测试通过。
- 部署后仅做只读状态、页面和模拟行为验证；真实 canary 必须另行获得明确确认。
